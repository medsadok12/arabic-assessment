# واجهات أكاديمية عارم — للأطفال من 6 إلى 13 سنة

المرجع الكامل في `CLAUDE.md` (الأقسام 2، 6، 7.2.1، 12.1). هذه خلاصته العملية. أي تعارض: `CLAUDE.md` هو الحَكَم.

## 1. الألوان

| الدور | القيمة | الاستعمال |
|---|---|---|
| الهوية | `#1A2B4A` | الترويسة، العناوين الكبيرة، نص الأزرار الذهبية |
| الإبراز | `#E8B84B` | كل زر رئيسي (CTA): خلفية ذهبية + نص `#1A2B4A` — لا العكس |
| فهيم | `#7C5CD9` | حصراً لكل ما يخص فهيم (الفيل) |
| الخلفية | `#F4EFE6` (أفتح `#FAF7F2`، أغمق `#EDE5D8`) | بدل الأبيض الصارخ |
| النجاح | `#2ABB7A` | علامة ✓ ورسائل الإنجاز فقط — ليس لوناً لأزرار عامة |

- اللوحة الخماسية لهوية الموقع. **أما ما يلعب به الطفل** (ألعاب، تدريبات، شاشات مكافأة) فيُبنى بألوان مبهجة زاهية من أول دفعة: تدرّجات، أزرار باستيل مختلفة، نجوم وقوس قزح.
- **صفر إحباط:** لا أحمر في أول ما يراه الطفل عند الخطأ. بدل الأحمر استعمل بنفسجياً أو كهرمانياً هادئاً، مع رسالة تشجيع ومحاولة أخرى. (`#b91c1c` استُبدل سابقاً بـ`#4338ca` لهذا السبب.)
- لا تغيّر اللوحة دون طلب صريح من الأستاذ محمد.

## 2. اللمس والخطوط والتخطيط

- **هدف اللمس ≥ 48px** لأزرار الطفل (44px حدّ أدنى مطلق في لوحات المعلم)، ومسافة كافية بين الأزرار — لا أزرار صغيرة متلاصقة.
- الخط: Cairo/Tajawal، أو `GameFont` في الألعاب. لا خطوط زخرفية. حجم نص الطفل لا يقل عن 18px، والكلمة المطلوب قراءتها كبيرة بتشكيلها الكامل.
- تباين عالٍ دائماً، ومساحات فارغة كافية، وشاشة واحدة = مهمة واحدة.
- `dir="rtl"` على حقول الإدخال العربية. احذر الخصائص الاتجاهية: `right` و`left` في RTL معكوسة بصرياً عمّا تتوقعه.
- **CSS قياسي فقط** (`globals.css` + كتل `<style>` للمكوّن). **ممنوع Tailwind** — غير مثبّت، وكلاساته أسماء ميتة.
- كتلة CSS ثابتة فيها `'` أو `"` أو `>` أو `&` (مثل `'Cairo'`، `content:''`، `.a > .b`) تُكتب `<style dangerouslySetInnerHTML={{ __html: \`…\` }} />` لا `<style>{\`…\`}</style>`. السبب: React يحوّل هذه الرموز على الخادم إلى `&#x27;` وأخواتها، فيفسد الـCSS ويُعاد رسم الجزء كله في المتصفح. الاختبار `lib/style-blocks.test.js` يمنع ذلك.
- قواعد الجوال داخل `@media (max-width: 640px)`. الجداول داخل `.table-scroll-wrapper`، وبطاقات الإجراءات بـ`.mobile-stack` (`-main` و`-actions` و`-act`). لا `overflow:hidden` على غلاف جدول.
- الطبقات: الترويسة والشريط السفلي على `z-index: 100`، وكل نافذة منبثقة أو لوحة سفلية على 200 فأعلى.
- على أجهزة اللمس، إن كانت هناك لوحة مفاتيح عربية على الشاشة، ضع `inputmode="none"` كي لا تنبثق لوحة الجهاز فوقها. اكشف اللمس بـ`(pointer: coarse)` أو `navigator.maxTouchPoints > 0`.
- احترم `prefers-reduced-motion` في الحركات الكبيرة (قصاصات الاحتفال، الاهتزاز).

## 3. النصوص الموجّهة للطفل

- تربوية ومشجّعة ومحفّزة. لا مصطلح تقني أبداً: لا "خطأ في الخادم" ولا "Request failed" ولا رسالة `e.message` خام.
- ❌ «إجابة خاطئة» ← ✅ «أحسنت المحاولة! لا تنسَ إضافة الهمزة: أَسَد».
- لا تكشف الإجابة قبل أن يحاول الطفل، إلا بتلميح متدرّج.
- رسائل لوحة المعلم مباشرة وواضحة (يجوز فيها ❌ وتفصيل السبب)، لكن بلا إنجليزية.

## 4. الأصوات (قاعدة 7.2.1 — لا تُكسر)

- صوت واحد في كل لحظة: عنصر `Audio` مشترك واحد، يوقف السابق قبل تشغيل اللاحق.
- «الحروف الهجائية» `/library/huroof`: **تسجيلات المعلم وحدها**. لا `/api/faheem/tts` ولا `speechSynthesis`، وبلا تسجيل = صمت.
- ممنوع `audio.play().catch(() => speak(...))` بلا حارس `if (ref.current === a)`.

## 5. لوحات المعلم داخل الألعاب

- ✏️ يفتح نموذج التعديل **تحت صف العنصر نفسه** ويُغلق بالزر نفسه، والقائمة لا تتحرك. استعمل `lib/edit-scroll.js`:
  - `keepRowInPlace(id)` قبل تغيير الحالة.
  - `returnRow(id)` عند الحفظ أو الإلغاء.
  - `revealBelow(formRef.current)` لإظهار أول النموذج.
  - `flashRow(id)` بعد الحفظ.
  - كل صف يحمل `data-edit-row={id}`، والنموذج يُعرض بعده داخل `<Fragment key>`.
- بعد الحفظ حدّث القائمة **بهدوء**: بلا شاشة تحميل تستبدل النافذة أو الجدول (`loadGameWords({ quiet: true })`). شاشة التحميل تُغلق النافذة وتعيد فتحها فيضيع مكان المعلم.

## 6. قائمة فحص قبل التسليم

1. ثلاثة أحجام: جوال 390×844 (لمس)، آيباد 820×1180، حاسوب 1280×800 — بلا تمرير أفقي للصفحة، وكل زر داخل الشاشة.
2. لا لون خارج اللوحة في عناصر الهوية، ولا أحمر عند خطأ الطفل.
3. كل نص للطفل مشجّع وخالٍ من المصطلحات التقنية.
4. أزرار الطفل ≥ 48px.
5. لقطة شاشة فعلية بـPlaywright لكل حجم، وانظر إليها بنفسك (المهارة `aarem-verify-ship`).
